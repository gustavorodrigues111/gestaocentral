Projeto › Subprojeto › Tarefa · Rotinas vs Demandas · multi-rest unificado

💡 Como ler

Hierarquia Projeto › Subprojeto › Tarefa. Projetos são as grandes áreas (Pessoas, Financeiro…), divididos em Rotinas (recorrentes) e Demandas (pontuais). Cada projeto tem cor (herdada pelas tarefas), dono, visibilidade. Cada subprojeto tem seu gatilho (se for automático), campos custom, pasta Drive padrão e tarefas-template. Edite à vontade.

📌 Pontos transversais já decididos (estão no design, não dá pra editar aqui)

  • Caixa de tarefas é POR USUÁRIO — independente do restaurante selecionado no topo do app. Quem atende múltiplos rests (escritório) tem tudo num lugar só. Tarefa pode ter restaurante como campo (não como contexto raiz).
  • Tarefas-lembrete vêm de cadastros mestres, não vice-versa — quando o trabalho é puxar "fato cadastrado no sistema" pra execução. Cadastros que geram tarefas automaticamente: Conta Fixa (módulo Financeiro: fornecedor + valor + PIX + recorrência → gera tarefa de pagamento na data), Prazo de Licença/Manutenção (tipo + fornecedor + periodicidade → gera tarefa X dias antes do vencimento), Admissão (gera 4-5 prazos trabalhistas: experiência 1ª/2ª, exames, coprocultura), Reunião agendada (gera tarefa-pai com subtarefas = itens da pauta), Folga programada (vira bloqueio na escala, não tarefa). A tarefa carrega linkOrigem que abre o cadastro mestre.
  • Co-responsáveis — tarefa tem 1 responsável principal + 0..N co-responsáveis. Co-responsáveis recebem as mesmas notificações e podem concluir, mas só o principal aparece em "Minhas Tarefas" do co-responsável (evita poluição). Útil em demandas colaborativas (ex: "Comprar Vinhos Puba" — Gustavo responsável, Janaynna co-responsável pra pagamento).
  • Anexos sobem pro Drive (na pasta definida pelo subprojeto), tarefa guarda só o link.
  • Log automático em cada tarefa: check/uncheck de subtarefa, comentário, anexo, edição de campo → registra autor + timestamp. Auditável.
  • Soft delete — tarefa excluída vai pra lixeira oculta. Master tem tela pra restaurar/auditar.
  • Cor do projeto é background do card da tarefa. Novos projetos: criador escolhe.
  • "Prazos Trabalhistas" não é projeto separado — é uma view transversal filtrando tarefas com tipo ∈ {Experiência, Exame Clínico, Exame Complementar, Coprocultura, Gozo de Férias}, ordenadas por vencimento. Fonte da verdade fica nos subprojetos de origem (Admissão, Férias, etc).

🧬 Anatomia da Tarefa (referência — não-editável)

Título + DescriçãoTexto livre.
Responsável principal1 pessoa.
Co-responsáveis0..N pessoas (recebem notificações).
PrazoData + hora opcional.
Statusa fazer / em andamento / concluída / cancelada.
Prioridadebaixa / normal / alta / urgente.
Checklist de subtarefasLista de itens marcáveis. Cada check vira entrada no log.
AnexosSobem pro Drive na pasta do subprojeto; a tarefa guarda só o link.
ComentáriosCom @menções (notificam). Entram no log.
Log de atividadeTudo que muda fica registrado com autor + quando.
Campos customDefinidos pelo subprojeto (ex: Empresa, Cargo, Tipo de exame).
CorHerdada do projeto.
Restaurante vinculadoOpcional. Algumas tarefas têm, outras são transversais.
Empresa(s)Multi-select. Tarefa pode pertencer a 1, várias ou todas as empresas. Campo padrão (igual ao Asana hoje).
Origem do cadastroDe onde a tarefa veio: avulsa (criada manualmente), conta-fixa (gerada pelo módulo Contas Fixas), manutencao (gerada pelo cadastro de manutenção), admissao (cascata de Admissão), ferias (gozo programado), reuniao (item da pauta), evento (subtarefa de evento), lote-financeiro (lote mensal). Clicar abre o cadastro mestre.
Tipo derivado (subcampo)Quando a origem é cadastro, alguns subprojetos usam um sub-campo discriminador: Experiência → 1ª/2ª, Exame Médico → Clínico/Complementar, Demissão → Empresa/Empregado/Acordo, Folha → Adiantamento/Salário.
